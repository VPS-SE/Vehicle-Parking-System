# Lot Map Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add four PES parking lots and a generated top-down plan of each lot. Drivers see where their slot is. Admins see live slot states and can find where a vehicle is parked by its registration.

**Architecture:** A pure function turns a lot's slots into a plan (bay rectangles, aisles, gate and route), which a server-rendered SVG partial draws. One service gives each slot's live state, and another finds a parked vehicle. Both reuse the existing occupancy rules. No new models, no migrations and no JavaScript beyond HTMX.

**Tech Stack:** Django 5.2, PostgreSQL 16, pytest, HTMX 2.0.4, the "Daylight" tokens in `static/css/vps.css`.

**Spec (agreed with the user in chat, 2026-11-06):**
- Four lots from an idempotent `python manage.py seed_pes_lots`, using an Indian mix that is mostly two-wheelers:

  | Name | TwoWheeler | Standard | EV | Accessible |
  |---|---|---|---|---|
  | PES RR Campus Front Gate | 100 | 30 | 4 | 2 |
  | PES RR Campus Back Gate | 200 | 80 | 8 | 4 |
  | PES EC Campus Engineering Parking | 180 | 70 | 8 | 4 |
  | PES EC Campus Medical Parking | 80 | 50 | 6 | 6 |

  Hours are 07:00 to 22:00. Tariffs are TwoWheeler ₹10, Standard ₹30, EV ₹30 and Accessible ₹20 per hour, effective today. Addresses: the RR lots use "PES University, 100 Feet Ring Road, BSK III Stage, Bengaluru 560085"; the EC lots use "PES University Electronic City Campus, Hosur Road, Bengaluru 560100".
- The plan is a generic Indian lot. The entry gate (boom barrier plus security cabin) is at the bottom left, traffic keeps left, and the exit is at the bottom right. Accessible and EV bays are nearest the gate, then rows of narrow two-wheeler bays, then car bays. Within a type, a lower `distance_rank` is never farther from the gate. Every bay is labelled with its slot code.
- Drivers see the plan on the booking confirmation page and on a "View map" page linked from My Bookings, for Reserved and Active bookings. Their bay is highlighted, and a dotted route runs from the gate to it.
- Admins get a "Lot map" page. A lot selector shows every bay coloured free, reserved, occupied or blocked. The page refreshes every 30 seconds through HTMX, like live occupancy. Searching by registration finds the vehicle parked now (an Active reservation), switches to its lot and highlights its bay with driver, booking reference and entry time. Clicking a bay shows its current holder.
- Accessibility: 0 axe violations. The SVG has `role="img"`, a title and a description, and there is a text alternative (a "Your slot" sentence for drivers, and a collapsible slot list for admins).

## Global Constraints

- Restyle and existing behaviour stay untouched: do not change existing text, URLs or tests. Add new tests only.
- Use only the CSS custom properties from `static/css/vps.css` (Daylight). New CSS goes in `static/css/pages/lotmap.css`, linked through `{% block extra_css %}`.
- Lot map page access: `function_required(Function.MANAGE_LOTS)`. Driver map: `function_required(Function.OWN_RESERVATIONS)`, owner only, 404 otherwise.
- Registration input is normalised with `vps.vehicles.services.normalise_registration`.
- Text contrast at least 4.5:1 (3:1 at 24px and larger). Every bay link has a 44px hit area through its group, or the slot list provides an alternative target.
- Commit messages: `type: 4 to 6 words`, with no trailers.

## Review Focus

1. A lot with zero slots, and a search for a registration that is not parked, must render a calm message and not crash. Tested in Tasks 1, 2 and 5.
2. Two Active reservations cannot share a slot, but a registration with an old Completed booking and a new Active one must return the Active one. Tested in Task 2.
3. Registration typed with spaces, a hyphen or lower case (`ka 05 dm-0001`) must still match. Tested in Task 2.
4. A driver opening another driver's map URL must get 404, not the other booking. Tested in Task 4.
5. Archived lots must not appear in the admin lot selector, and their maps must not be reachable. Tested in Task 5.

### Task 1: Lot plan geometry (`vps/lots/plan.py`)

**Files:**
- Create: `vps/lots/plan.py`
- Test: `tests/test_lot_plan.py`

**Interfaces:**
- Produces:
  - `Bay(slot_id: int, code: str, slot_type: str, row: int, x: int, y: int, w: int, h: int)`, a frozen dataclass with properties `cx`, `cy` (centre). `row` is 1 for the row nearest the gate.
  - `Rect(x, y, w, h)`, frozen.
  - `LotPlan(width: int, height: int, bays: tuple[Bay, ...], aisles: tuple[Rect, ...], entry: tuple[int, int], exit: tuple[int, int])`, with:
    - `bay_for(slot_id) -> Bay | None`
    - `route_to(slot_id) -> tuple[tuple[int, int], ...]`
  - `build_lot_plan(slots: Iterable[Slot]) -> LotPlan`. It reads only `pk`, `code`, `slot_type` and `distance_rank`.
- Constants:
  - `WIDTH = 1000`.
  - Left driveway 70 wide (x 0 to 70); bays start at x = 90.
  - Two-wheeler bay 20×44.
  - Car-sized bay (Standard, EV, Accessible) 40×70.
  - Aisle 60 high after every second row.
  - Gate band 90 high at the bottom.
  - Zone order nearest the gate first: Accessible, EV, TwoWheeler, Standard.

### Task 7: Dynamic, premium map layer (user requirement, 2026-11-06: "very dynamic, like posh and premium websites")

Tasks 4 and 5 render a complete, accessible map without JavaScript. This task adds one vanilla ES module that progressively enhances it. With JavaScript off, everything still works.

**Files:**
- Create: `static/js/lotmap.js`, loaded with `<script type="module">` on the two map pages only. No frameworks and no CDN.
- Modify:

The `reg`, `ref`, `driver` and `since` fields appear only when a reservation exists.
  - Add `parked_vehicles_json(request)` at `lots/map/parked.json` (MANAGE_LOTS), returning `[{"reg": .., "lot_id": .., "slot_id": .., "code": ..}]` for search suggestions.
- Test: `tests/test_lot_map_json.py` covering both endpoints' shape, access (403 for driver and attendant), and the absence of fields for free slots.

**Behaviour (`lotmap.js`):**
- **Camera.**
  - Smooth pan and zoom: wheel or trackpad, pinch on touch, drag to pan.
  - On-screen + / − / "Fit" buttons and keyboard `+ - 0` plus the arrow keys, done by animating the SVG `viewBox` with requestAnimationFrame (eased, about 450ms).
  - Zoom is clamped to between 1× and 6×.
- **Fly to.**
  - On load with a highlighted bay, the camera eases from the full lot to the bay, about 900ms.
  - The bay's glow pulses.
  - The route draws itself (an animated `stroke-dashoffset` from the gate to the bay), and a small car or scooter marker glides along it.
- **Hover and focus card.** A floating glass card follows the pointer, or sits beside the focused bay. It shows the code, type, state chip and, for admins, the registration, driver, booking reference and how long ago they entered ("parked 1 h 12 m"). Bays are keyboard-focusable (`tabindex=0`), and Enter opens the detail panel.
- **Live updates (admin).**
  - Polls `state.json` every 10s, and pauses while the tab is hidden.
  - Changed bays cross-fade colour (CSS transition) and get a brief ripple ring.
  - The four counters (free, reserved, occupied, blocked) above the map count up or down with a rolling-number animation.
  - Shows "Live · updated 3 s ago".
  - This replaces the 30-second HTMX full refresh when JavaScript is on.
- **Search (admin).**
  - Search-as-you-type with suggestions from `parked.json`: debounced, matching on normalised registration, arrow keys and Enter to choose.
  - Choosing a suggestion switches lot (fetching that lot's map panel if needed), flies to the bay, and opens the card.
  - Esc clears it.
- **Filter chips (admin).** Chips for state (Free, Reserved, Occupied, Blocked) and type (2W, Car, EV, Accessible). Non-matching bays dim to 15% with a transition. Counts are shown on the chips.
- **Mini-map (admin).** A small inset overview in the corner showing the current viewport rectangle. Clicking it jumps there.
- **Motion.**
  - Under `prefers-reduced-motion: reduce`, all camera moves are instant, no route draw or marker, no ripples and no rolling numbers.
  - Use `transform` and `opacity` only, so there is no layout thrash. Target 60fps on a 300-bay lot.
- **Accessibility.**
  - Every control is reachable by keyboard and has a visible focus ring.
  - The card content is mirrored in an `aria-live="polite"` region when a bay is focused or found.
  - Still 0 axe violations.
